# Velocity Quest アプリ設計書

2026-11-08 時点。正本は claude.ai 上のドキュメント「Velocity Quest アプリ設計書」。

## 概要と目的

Velocity Quest は、競泳のスプリント力を伸ばすために、ジムとプールの練習を記録し、その伸びを競技記録と並べて確かめる Web アプリ。単なる練習日誌ではなく、「どの練習の伸びがタイムにつながったか」を自分で判断できる材料をそろえることが目的。

| 項目 | 内容 |
| --- | --- |
| 対象の競技 | 競泳のスプリント(25m・50m、4泳法、短水路のターンを含む) |
| 利用者 | 自分と仲間。各自が自分のアカウントで使い、データは人ごとに分ける |
| 端末 | 1人が複数のスマホで使う。同じ人の端末間で同期する(段階3) |
| 練習の考え方 | マケボイの方法のエッセンスを簡素化した6原則(別ドキュメント「プリセット叩き台」) |
| デザイン | 黒とオレンジを基調にしたダークテーマ。アクセント色は変更できる |

## 技術構成と同期の方針

| 項目 | 方針 |
| --- | --- |
| 形式 | PWA(index.html、manifest.json、sw.js、アイコン)。GitHub Pages で公開 |
| ファイル構成 | 機能ごとに複数のファイルに分ける |
| 端末内の保存 | IndexedDB(localStorage は使わない) |
| 同期(段階3) | Firebase Firestore + Google ログイン。オフラインで記録し、電波が戻ったら自動で同期 |
| バックアップ | JSON での書き出し・読み込みを最初から用意する |

### 後から同期を足すための決まり

1. データの読み書きを1か所(読み書き専用の層)にまとめ、画面の処理から保存先を直接操作しない。
2. すべてのデータに UUID、最終更新日時、削除フラグ、端末ID を持たせる。削除は消さずにフラグで表す。
3. データ構造にバージョン番号を持たせ、形を変えたときに古いデータを自動で変換する。
4. 種目は名前ではなく ID で参照する。

### 仲間に配るときの注意(段階3)

- Firebase の設定は管理者が1回行う。仲間は「Google でログイン」だけで使える。
- LINE などアプリ内のブラウザでは Google ログインが失敗するので、Chrome や Safari で開くよう画面で案内する。
- iPhone はホーム画面に追加して使ってもらう。

## 画面構成と主な機能

下部ナビ:「ホーム」「トレーニング」「指標」「履歴」。設定はホーム右上。

| 画面 | 主な機能 | 試作 |
| --- | --- | --- |
| ホーム | 目標を上部に常に表示(目標値、ベスト、あと何秒、期限まで何日)。今日の体重の入力。ルーティンからワンタップで開始 | design/Main.dc.html |
| トレーニング記録中 | 経過時間。休憩タイマー(30秒・1分・90秒・2分・3分PAP・任意)。重さの内訳(バー+プレート片側×2=合計)。セットごとの重さ・回数・感触(顔5段階)・メモ・完了。ウォームアップの区別。片側の切り替え(両側/片側・左右同じ/片側・左右別)。前回と自己ベスト。種目の追加・削除・並べ替え | design/Workout.dc.html |
| 種目を選ぶ(ルーティン作成) | 部位のタブ、器具の絞り込み、検索、「片側可」の印、自分で種目を登録 | design/Picker.dc.html |
| 指標と目標 | 目標の一覧。推移を重ねるグラフ(段階2)。立ち幅跳び・垂直跳びの試技 | design/Metrics.dc.html |
| タイム入力(プール、段階2) | 条件の選択で記録先の系統を自動決定。数字キーパッド。今日の記録、最高・平均、打ち切りの判定 | design/TimeEntry.dc.html |
| 履歴 | 日付ごとの練習の一覧と詳細 | 未 |
| 設定 | 単位、器具ごとのバーの重さ、種目ごとの重さの刻みとタイマーの初期値、計測方法の初期値、テーマの色、書き出し・読み込み | 未 |

共通の動き:

- トレーニング中は画面を消灯させない。
- ルーティンは「ひな形」で、当日の記録はそのコピー。トレーニング中に種目を変えても元のルーティンは変わらず、終了時に「ルーティンにも反映するか」を確認する。
- PAP のペアを登録しておくと、1つ目の種目の完了で自動的に3分のタイマーが始まる。
  - ペア = 重い種目を数回行い、3分ほど休んでから似た動きを素早く行う組み合わせ(例:重いスクワット → ボックスジャンプ)。

## データ構造

すべてのデータに共通項目(UUID、作成・更新日時、削除フラグ、端末ID、所有者)を持たせる。

| データ | 主な項目 | つながり |
| --- | --- | --- |
| 種目 | 名前、主な部位、補助的な部位、器具、記録の型、片側で行えるか、重さの刻み、休憩の初期値、使う器具(バーの重さ)、非表示フラグ、最初から入っている種目か | ルーティンとセットから参照 |
| 器具 | 名前(例:ジムAのスミス)、バーの重さ | 種目から参照 |
| ルーティン | 名前、種目の並び(種目、予定のセット×回数、強度、休憩)、PAP のペア | 当日の練習のひな形 |
| 練習(ジム) | 日付、開始・終了時刻、元にしたルーティン、その日の体重、メモ | セットを持つ |
| セット | 種目、順番、ウォームアップか、左右の方式(両側/片側・同じ/片側・別)、重さの内訳(バー・プレート・加重・アシスト)、合計の重さ、回数(左右別のときは左右それぞれ)、時間・距離・高さ、感触(1〜5)、メモ、完了 | 練習(ジム)に属する |
| 練習(プール) | 日付、環境(短水路・長水路・貸し切り)、メモ | タイムを持つ(段階2) |
| タイム | 距離、泳法、プール、スタート方法、計測方法、器具(その他は自由入力)、タイム、有効か | 条件の組み合わせで系統を決める(段階2) |
| 系統 | 条件の組み合わせ(自動)、表示名、色 | タイムを束ねる(段階2) |
| 試技 | 種類(立ち幅跳び・垂直跳びなど)、日付、各試技の値、ファウル | 体力テストの記録 |
| 体重 | 日付、体重 | 実負荷・体重比の計算に使う |
| 目標 | 指標、目標値、良い方向(大きい/小さい)、期限、上部に表示するか | ホームに表示 |
| 設定 | 単位、計測方法の初期値、テーマの色、強度の段階 | 人ごとに1つ |

## 記録の型と計算ルール

| 記録の型(キー) | 入力するもの | 種目の例 |
| --- | --- | --- |
| 重さ×回数(`weight_reps`) | 重さ(内訳つき)、回数 | スミス系、ダンベル、ケーブル、マシン |
| 自重+加重(`bw_plus`) | 加重、回数(実負荷=体重+加重) | 懸垂(加重) |
| 自重−アシスト(`bw_minus`) | アシストの重さ、回数(実負荷=体重−アシスト) | 懸垂アシストマシン |
| 回数のみ(`reps`) | 回数 | ハンギング・レッグレイズ、スパニッシュ・スクワット |
| 時間(`time`) | 秒数 | プランク |
| 高さ×回数(`height_reps`) | 台の高さ、回数 | ボックスジャンプ、デプスジャンプ |
| 接地回数(`contacts`) | 接地回数、時間 | アンクルホップ |
| 距離+バンド(`distance_band`) | 距離か歩数、バンドの強さ | モンスターウォーク |
| 試技(`trials`) | 各試技の値(複数)、ファウル | 立ち幅跳び、垂直跳び |

### 計算ルール

| 項目 | ルール |
| --- | --- |
| 合計の重さ | バー+プレート片側×2。内訳と合計の両方を保存する |
| 推定1RM | エプリーの式(重さ × (1 + 回数/30))。10回以下のセットだけを使い、加重懸垂は体重+加重で計算する |
| 体重比 | 実負荷 ÷ その日の体重(その日の記録がなければ直近の体重) |
| 試技の集計 | 最高と、ファウルを除いた平均 |
| 系統(段階2) | プール・距離・泳法・スタート・計測方法・器具が同じタイムを1つの系統にまとめる(長水路の25m は短水路の25m と別) |
| 打ち切り(段階2) | 最初の3本の平均より3%遅いタイムは「目安超え」とし、平均から外して終了を提案する |
| 調子の確認 | 練習前の垂直跳び3回の平均が直近の平均より5%以上低い日は、強度を下げることを提案する |
| 全力の予算(段階4) | 1回の全力の合計は80秒まで(導入は60秒) |

入力の選択肢:スタートは「壁を蹴って/飛び込み」、器具は「なし/フィン/パドル/フィン+パドル/その他(自由入力)」、計測方法は「指ウォッチ/仲間/動画/大会公式」、感触は顔の5段階とメモ。

## 指標・目標・グラフ

練習タイムの系統、大会記録、推定1RM、跳躍、体重をすべて「指標」として同じ時間軸に並べる。グラフは判断の材料を見せるもので、「効果があった」と自動で判定する機能は作らない。

### 目標(段階1)

- 指標、目標値、良い方向(タイムは小さいほど良い)、期限を設定する。
- 上部に表示する目標を選び、ホームに「目標値・現在のベスト・あと何秒(何m)・期限まで何日」を常に表示する。

### 推移を重ねるグラフ(段階2)

| 項目 | 仕様 |
| --- | --- |
| 重ねる数 | 最大5系統 |
| 見分け方 | 系統ごとに色と線の形(実線・破線・点線・点のみ)を変える。色は変更できる |
| 表示方法 | 「推移の形」(既定。最初の値を0、期間内の最も良い値を100にそろえる)、「改善率」(基準日からの%)、「実数」(秒と kg の2軸) |
| 伸び幅 | 系統の一覧に実際の変化(−0.34秒、+14% など)を並べる |
| 1回の練習の代表値 | 最高値と、有効な本数の平均値を選べる |
| データの少ない系統 | 月1回程度のものは、線でつながず点だけで表示する |
| 期間の区切り | 最大筋力期・パワー変換期・レース特異期などを背景の帯で示す |

グラフの下には「同時に伸びていても因果とは限らない」という注意を常に表示する。

## 開発の段階

| 段階 | 内容 | 終わりの目安 |
| --- | --- | --- |
| 1 | ジムの記録(ルーティン、セット、タイマー、片側、重さの内訳)、最初から入っている種目、体重、試技、目標の表示、JSON の書き出し・読み込み | 自分のジム練習を1か月記録できる |
| 2 | プールのタイム入力、系統、打ち切りの判定、推移を重ねるグラフ | 練習タイムと推定1RM を並べて見られる |
| 3 | Firebase による同期と Google ログイン | 2台のスマホで同じ記録が見られ、仲間が使い始められる |
| 4 | 段階別のプリセット(陸上・プール)、PAP のペア、全力の予算の表示 | プリセットから練習を始められる |
| 5 | 目標と期間から練習を提案する機能 | 大会日を入れると段階が割り振られる |

## 未決の点

- タイム入力の距離に15m・20m・30m・35m・40m を加えるか
- 全力の予算に、壁キックなど抵抗をかけた全力の時間も含めるか
- 期間の長さを固定にするか、大会日から逆算して自動で割り振るか
- 履歴と設定の画面の試作(段階1では試作なしで、他の画面に合わせて作る)
- プールのプリセットを原則に合わせて作り直す(段階4までに)

SportCount には書き出し機能がないため、練習タイムは手入力が前提。
